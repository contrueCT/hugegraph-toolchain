# 新版本探索成本与整任务预算调整提案

2026-10-24，用户已确认单次探索；已确认整任务时间上限，并补充“允许配置吧，默认整次”。以下为新版本实现范围；不改变005、既有quick或任何已冻结计划。目标继续是全11题逐题吞吐—延迟曲线与独立确认的最高观察正确吞吐，统计认证单列可选。

## 探索只负责选点

现有探索固定每点2配对/4个新JVM。单模式11题×4速率=44点/176臂；10秒预热+30秒测量固定需要7040秒（1小时57分20秒），启动、验证、分析和清理另计。

新版本每点执行一次，保持44点全部计划及分母，固定窗口合计1760秒（29分20秒），最多44次目标启动。此阶段只生成描述曲线、失败和候选，不作配对差异推断或确认成绩。低速点P99样本不足仍unknown。只测单模式的单点，保持同机串行、正确性/原始证据/资源与逐题边界停止规则。

独立确认继续使用全新观测；确认点和重复成本单独预览，正式跨模式比较保留平衡顺序。首个增量不引入同一JVM跨速率复用；按题复用可把启动压到约11次，但涉及历史效应和编排改造，后置。

## 整任务预算作为真正硬截止

现有quick唯一真实观测为544.146秒，固定测量/预热216秒；其余328.146秒是合并生命周期开销，不能全部当目标启动时间。这个观测排除此前plan/prepare，报告另需时间，样本仅1次、置信低。现有规划要求至少4156000ms安全上界，不应把各阶段最坏上限相加当用户运行预算的最低值。

新版本默认按下式执行，并允许显式选择保守阶段预算模式；预览、计划和结果记录所选模式：

```text
用户整任务硬截止
  ├─ 剩余工作时间 = 总剩余 - 显式清理保留
  ├─ 当前阶段可用 = min(该阶段上限, 剩余工作时间)
  └─ 耗尽：停止后续，保留partial/budget-exhausted与完整分母
```

预算至少容纳固定工作窗口、必要前置及清理保留；预算不保证成功，不自动缩题/缩窗口/减重复。默认整任务模式下，各阶段仍有独立上限，但不会把上限之和强制作为最低总预算。保守模式额外要求总预算覆盖阶段最坏上界之和。容器TTL、task外层截止和取消宽限须使用同一总体期限，旧规则原样保留。运行前并列展示题数/率数/测量次数/JVM启动数、固定测量时间、历史同配置参考（若有）、开销与硬截止；不会将安全上界冒充ETA。

## 执行顺序

先收尾当前包验证；005原执行继续。剩余M2每项校准对应明确风险、最少运行数、证据复用范围和完成条件，优先产出实际可用的quick与低重复standard。原始请求、答案校验、必要资源证据保留；精细GC/JIT关联等已有增强按当前执行边界处理，不增加本轮前置。
