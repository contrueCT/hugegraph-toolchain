# HG-Bench 大图评测计划

主基线使用官方 LDBC SNB Interactive v1 固定资产。已有 SF0.1 产物保留为开发历史证据，不再安排小规模试跑。
用户已确定正式大图基准使用 **SF100**；每档单独锁定数据、参数、更新流、driver 和参考结果来源。
实际规模以完整资产的逐表行数为准。SF 标签与压缩文件大小都不能代替 HStore 的实际存储量。

## 规模与环境一起定义

| 档位 | 用途 | 进入测量的条件 |
| --- | --- | --- |
| SF100 | 正式大图性能基准 | 三个官方压缩资产及 119 个成员已冻结；实际转换/导入、独立答案和性能验证待执行 |

数据准备和执行面向专用环境设计，本机不下载试跑档。SF100 是固定的正式数据规模，
实际访问工作集、缓存和集群资源的关系需要在报告中披露，不因缓存命中而隐式更换数据规模。
后续若扩展规模，应作为独立配置和结果系列。
每次报告同时记录：总逻辑数据、各 Store 的主/副本数据与索引占用、JVM/引擎缓存配置、各节点可用内存、
实际请求涉及的分区和节点、缓存命中与磁盘读取。只用“总数据大于单机内存”不足以判断查询是否受存储约束。

## 可复现链路

```text
官方同规模资产 -> SHA-256 锁 -> 流式逐表清单 -> HG 映射与批量导入
                                                |
                                   点边计数 / ID / 端点 / 属性核对
                                                |
                                   同规模参考结果 / 更新顺序验证
                                                |
                               HStore 拓扑、分区、副本与缓存状态记录
                                                |
                                 A/A 重复 -> 负载阶梯 -> 版本对比
```

各步骤单独保存状态和证据。资产完整性通过后，导入、查询正确性和性能阶段仍分别待验收。
SF0.1 的答案与验证通过率不能移用到目标大图。已有 29 类操作的本地单元验证仍不能替代真实 SF100/HStore 验证。

## 导入与运行协议

1. 使用隔离的新图，锁定 schema、转换器、Loader 版本、批次与并发。先按冻结清单和转换产物核算输入数据、
   转换输出、临时索引、数据库索引/副本和恢复副本所需空间，并保留失败重试余量。
2. 转换采用流式读写；跨表关联和重复/端点检查使用磁盘索引。直接归档的两遍转换、GZIP 分片和有界 SQLite 索引已完成手写边界验证；
   在目标大图上的吞吐、额外空间和恢复能力需要单独验收，不能因流式读取就认为整个导入已满足大图要求。
3. 按顶点/边标签保存源记录数、导入成功/失败数、库内计数与全分片完整属性证据；平行边、64 位 ID、日期和多值属性需核对。
   保存导入耗时和资源记录，独立于查询性能成绩。
4. 导入结束后等待索引、分片迁移和压缩达到所声明的稳定条件；记录观测区间及实际状态。
   若评测迁移/压缩干扰，则单列该实验并固定触发方式。
5. 记录 PD/Server/Store 数量、Store 分区分布、副本数、节点硬件/限制、版本和配置。
   没有多 Store 与跨节点请求的证据，不标为分布式扩展性测量。
6. 每轮恢复同一初始状态与更新流位置；官方完整 track 遵循固定 driver 的时间安排与依赖。
   只读子集、Kout 和自定义并发负载分别标为 HG 扩展。

## 验收与后续环境工作

本地规范/组件继续交付；用户提供的扩容 Linux VM 已完成受控 SF100 资产捕获。单机多 Store 的部署与重任务预算仍需确认，用于：

- 导入后确认工作集/缓存关系，披露 SF100 在目标环境中的工作集与缓存关系。
- 校验实际分布式执行和对应规模的查询正确性。
- A/A 重复估计噪声，以负载阶梯确认服务端和客户端瓶颈，再做版本 A/B。
- 固定数据量增加 Store 节点的扩展实验，和随资源同步增加数据/负载的实验分开报告。
- 独立环境复现与完整证据审查。

本地资产下载、结构统计与断点续传验证均不构成 HugeGraph 性能成绩。

默认记录单分区更新流；如正式 driver 需要调整更新分区数，必须生成独立资产锁并在计划中明确记录。

2026-10-22：图 CSV 实际约 79.2 GB；初始归档总展开 108.5 GB 中包含内嵌更新流。导入严格区分图表与更新；正式更新选用独立 updates 资产。forum 两份流 hash 不同，不能把历史 SF0.1 的逐字节相同结论套用到 SF100。
