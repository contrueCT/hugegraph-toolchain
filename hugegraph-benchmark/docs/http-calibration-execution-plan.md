# HTTP 校准执行与验收边界

2026-10-23：依据用户收口主线的要求，近期工作固定为下列顺序。保留原 M0–M4 和 SF100 全部验收归属。

| 顺序 | 真实执行与交付                      | 完成条件                                                                                              |
| ---- | ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 1    | 同构建、同模式的独立 A/A experiment | 预先冻结全部题目、负载、配对顺序、种子、统计族和资源预算；执行、原始重算、区间及 unknown 原因均可追溯 |
| 2    | 人工注入的已知退化及未修改对照      | 明确注入位置、大小及预注册判据；真实请求/正确答案、独立配对和原始证据重算；报告实测检出和未检出       |
| 3    | 驱动余量与预热稳定性                | 负载阶梯、驱动 CPU/事件循环/丢弃及目标状态；观察多个窗口，依据结果选定正式负载与相同预热              |
| 4    | 采集、校验和 trace 成本             | 受控配对比较与资源预算；正式正确性验收保持答案校验开启；有影响或无法分离的成本明确披露                |
| 5    | 正式参数冻结及 forward/embedded     | 核心校准条件通过或明确限制适用范围后，冻结同构建单变量比较，保留所有题目、区间和不确定项              |

必要条件继续覆盖正确答案、请求计数守恒、完整响应的单调耗时、构建和实际配置一致、显式环境干扰检查与独立重复。
任务完成、报告生成及少量 A/A 无误判都不能直接证明性能有效或误判率已校准。
P99 的最小观测数保持当前预声明门限，未达到的单元格保留 unknown；不为首组短窗口降低门限。
少量 experiment 只给实测噪声、决策和区间，不宣称已验证名义 5% 误报率。

精细 phase→宿主资源窗口映射、跨进程运行时证明及 JVM 事件归因暂时退出核心校准关键路径。
已有实现与证据保留，原始观测继续收集；未建立窗口映射时不发布逐 phase 资源/GC 成本结论。
新增增强组件需指明它解决的实际实验阻塞和有限完成条件，不继续扩展核心校准的前置集合。

已完成的 v6 保留原 attempt：一项预热质量失败使整组无效，不能改阈值、补造配对或重跑覆盖。
近期 A/A 使用新的计划、独立 experiment/JVM 和唯一 request 身份；沿用既有可用执行栈，不等待增强项接线。
运行前与 experiment 之间复核声明的大图重作业已终止；受保护的 d6 空 HStore 和其他常驻服务继续披露。
该检查不等于整个主机独占，也不能排除 VM 层竞争。
