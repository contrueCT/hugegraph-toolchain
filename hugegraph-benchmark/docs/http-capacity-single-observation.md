# 单次探索与可配置总预算

用户于2026-10-24确认：探索每个点运行一次，独立确认保留新数据与重复；预算允许配置，默认整次任务。当前实现已通过本地专项和正向端到端协议联验，尚未执行真实HugeGraph容量曲线。已有A/A005和旧冻结计划不变。

```text
全11题 × 每模式 × 已声明速率
        |
        v
每点1次新目标/driver运行 -> 记录正确吞吐与延迟 -> 选择候选及邻点
                                                 |
                                                 v
                           新计划/新数据，4配对共8臂独立确认
```

探索不产生配对差异推断。样本不足的P99为unknown；最高观察点保持未确认。独立确认不能复用探索的run ID、raw或执行目录；原始失败及未执行点留在报告中。每点使用新JVM，首版没有跨速率复用目标进程。

单模式默认示例为11题×4速率，共44次运行；10秒预热加30秒测量的固定工作量为29分20秒。另有44次目标启动、功能检查、采集和清理；此数值不是预计完成时间。确认点数与成本在确认计划中另行展示。

## 用法

```sh
hgbench http capacity plan --project project.json \
  --policy examples/http-capacity-policy-v2.json --out new-study --dry-run
hgbench http preset plan --project project.json --preset quick \
  --budget-mode total --budget-ms 1200000 --out new-quick --dry-run
```

容量policy v2和确认request v2使用顶层 `budgetMode`，未填写时为 `total`。quick公开入口使用 `--budget-mode`。可选值：

| 模式 | 时间含义 |
| --- | --- |
| `total`（默认） | 启动本次执行后，共享一个总截止；包含执行前验证、目标启动、测量和收尾。每阶段有上限，实际可用时间还受总剩余时间限制。 |
| `stage-sum` | 额外要求总预算覆盖全部阶段的保守最大耗时。保留原有保守规划方式。 |

例如20分钟总预算不会承诺20分钟内完成所有测量。工具提前留出停止和证据收尾时间，耗尽时停止后续派发，记录部分结果、停止原因和全部未完成点；不减少题目、重复或测量时长来凑成成功。取消/故障回收仍有外层监督；超出预算或无法证实清理时保持失败或未证实，不能声称预算内完成。

`plan`、事前 `prepare` 和事后独立离线 `report` 有各自显式预算，不计入已经启动的测量任务；预览会区分这些阶段。预算是执行约束，历史耗时只是带配置及范围说明的参考，不能把各阶段上限之和当正常ETA。

旧policy v1继续生成原四臂探索，旧confirmation request v1及旧preset绑定按原规则重验；重建旧记录应使用对应冻结实现。当前工作区的新源码不能替换正在执行的冻结源码。
