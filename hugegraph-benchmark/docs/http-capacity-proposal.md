# HTTP standard/full：已确认的吞吐主线范围

**用户已确认范围，容量执行与校准尚未验收。** 默认主结果为：固定资源下，全11题逐题的吞吐—延迟曲线，
以及独立复测、证据有效且驱动余量充足的点中，最高观察正确吞吐（correct requests/s）。
没有业务SLO时继续测曲线，不发明阈值，也不将观察最高点称为SLO容量或无条件可持续极限。
事前提供并冻结延迟/错误SLO后，再派生相应SLO容量。固定负载延迟为补充。
用户已确认采用工程验收，真实误报率统计认证单列可选。

| 档位     | 推荐范围                                                          | 交付                                                          |
| -------- | ----------------------------------------------------------------- | ------------------------------------------------------------- |
| standard | 全11题逐题曲线；固定一种编码、候选构建和资源配置                  | 最高观察正确吞吐、独立确认结果与受限原因；有SLO时另报容量范围 |
| full     | 扩充开放/闭环阶梯、编码及资源等预声明分层；需要时加入业务混合负载 | 各分层曲线/观察吞吐、独立实验；可选SLO容量及更强统计认证      |

逐题结果分别报告；启用SLO时组成逐题容量向量，不直接相加或平均成一个“数据库QPS”。业务混合容量必须另行固定题目比例、
数据/缓存状态和到达过程；目前没有业务比例，暂不生成混合成绩。
这11题衡量HTTP执行入口、序列化和响应路径；SF100/HStore大图的原验收范围保持。

## 推荐流程

```text
固定项目/资源/搜索规则，可选事前SLO
         ↓
逐题开放负载阶梯 → 完整吞吐、延迟、错误、driver压力曲线
         ↓
冻结独立确认点：候选最高点及邻近安全点
         ↓
独立新JVM、平衡A/B复测 → 曲线、观察最高点及限制
```

1. **先校准可测范围。** 校验全部答案、驱动余量、固定预热/测量窗口和观测成本；校验、解压与trace保持开启。
   driver CPU/事件循环/调度、客户端丢弃或证据预算受限时标记 `driver-limited/unknown`，
   保留已确认观察值，启用SLO时可报告通过点下界；不能把驱动受限点当作target容量上界。共机d6等干扰继续披露。
2. **探索边界。** 按预注册的起点、递增/细化规则和最大点数，逐题、逐负载点创建独立现有计划/attempt。
   保存所有通过、超SLO、失败和未执行点；探索结果用于选点，不承担最终容量结论。
   双方从共同探索网格开始，按各自停止规则保留已测和未执行点；不为补齐网格继续压过已证实的服务边界。
3. **独立确认。** 新计划冻结候选最高点、邻近安全点、顺序和种子；建议至少4个平衡独立配对，
   固定相同预热、测量与资源，检查吞吐/尾延迟趋势和未完成请求是否积累。
   窗口不足、不稳定或证据不足保留unknown。双方仅在共有实测点比较同负载结果，其余边界分别报告。
4. **按实测网格报告。** 默认取已独立确认的最高观察正确窗内吞吐；同时给实际到达率、P50/P95/P99、错误/超时、
   丢弃、窗后完成及资源诊断。可选SLO容量只使用确认达标点：最高点仍通过时仅报下界；
   相邻上点确由目标超SLO且驱动余量有效时才报边界区间，不插值成精确极限。
   “可持续”仅限满足预声明约束、在已确认负载和时长内无积累的范围。

开放阶梯展示到达率、正确吞吐与延迟的关系，配置SLO时验证相应约束；full可补闭环并发曲线。
两种负载模型分别报告。固定低速open的goodput若等于到达率，按交付质量/描述值处理；
不会用零方差bootstrap宣称吞吐等价。该指标角色调整须纳入新版本政策，旧004和quick定义保持。

## 运行前冻结的参数与停止规则

| 必须预声明   | 内容                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 可选服务目标 | 使用SLO容量时，事前固定端到端延迟分位/上限、错误/超时/迟到限制和适用题组        |
| 工作负载     | 全题目/分层、编码、开放速率/闭环并发、在途上限、搜索步幅和边界分辨率            |
| 独立复测     | 固定预热/测量窗口、区组/实验数、重置方式、顺序/种子、完整统计族、阈值及样本政策 |
| 硬预算       | 每点/每臂/全程时间、请求/trace/响应/磁盘、CPU/内存、停止宽限及剩余空间          |

达到预声明探索上限或服务边界后停止加压，执行安全范围内原定确认点；达到资源/安全/取消阈值立即沿原身份停止并保留partial。
预算耗尽时报告未定位或未完成，不自动缩短窗口、跳题、降低配对或改SLO。
P99仍要求每题/负载/物理臂至少1000个正确观测；不跨题、跨臂合并凑数。
全11题、多个阶梯和独立复测的耗时由实际参数推导，不能承诺15–30分钟完成全部P99容量验收。

## 已确认范围与工程定值

用户已确认：**standard默认交付全11题单题曲线和独立复测的最高观察正确吞吐；业务SLO作为可选容量派生，
full再扩充分层及具有真实比例的混合业务。** 未提供SLO或混合比例不阻塞逐题曲线。
探索速率、步幅、点数、时长、资源与停止预算由工程预注册并展示依据，具体数值待工程校准；
这些参数不再列为待用户选择，也不因范围已确认而宣称数值已校准。

实现继续复用公开 `generate/profile → comparison plan/prepare → task → report`，不新增执行生命周期。
当前planner固定latency+goodput整族，analyzer对错误/drop/驱动压力设有原质量门；新政策还需区分
“测量证据无效”和“有效测量超出服务约束”，实现容量汇总与受限原因。不能以改标签清除原问题或追认旧结果。
