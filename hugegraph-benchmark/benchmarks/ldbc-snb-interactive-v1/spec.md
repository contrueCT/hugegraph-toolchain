# HG-Bench SNB Interactive v1 / SF100

版本：`0.1.0-draft.3`。本包是可离线校验的规范候选；发布门槛见 `release.json`。
题集身份、测量计划身份、数据库运行证据分别记录，文件校验成功只证明本包完整。

## 用途与边界

评测分布式 HugeGraph 在大规模社交图上的关联读取与持续写入能力。
正式规模固定为 SF100，数据来自官方预生成 CsvBasic / LongDateFormatter 资产。
相同 SF 的不同生成器版本、序列化格式、更新分区和文件内容不能混用。
SF0.1 历史证据仅覆盖早期映射验证；本包不使用它代表 SF100 的答案或性能。

```text
固定官方初始图 + 参数流 + 更新流
                 |
          相同数据状态与映射
            /             \
     独立参考数据库      HugeGraph / HStore
            |             |
       有序参考记录  <-->  有序执行观测
                 |
          答案与提交状态验证
                 |
       校准后的固定测量协议
                 |
     逐类成绩 + 资源 + 完整证据
```

本 track 使用官方 driver 的调度、依赖与短查询派生逻辑。修改操作比例、挑选 ID、去掉更新、
截断复杂查询或改用自定义闭环负载，应创建 HG 扩展 track 并保留独立身份。
原生图 REST 指 `/graphs/{graph}/vertices`、`edges`、`traversers/*` 等结构化图 API；
REST Gremlin 是 REST 服务的 `/gremlin`，直接 Gremlin 是 Gremlin Server 的协议入口。
本包不预设三者均能表达完整 LDBC 工作负载，适配器逐项声明能力。

## 题集与语义权威

`tasks.json` 完整列出 IC1–IC14、IS1–IS7、IU1–IU8：题名、driver 类型、参数、结果字段、
默认 limit、参数来源、比较方法以及对应的固定版本查询/Java 源文件。
`reference/sources.lock.json` 为每个上游文件记录仓库、commit、路径、大小与 SHA-256。
源文件按原字节保存，许可证与 NOTICE 随包保留；上游源码不参与本地重写。

| 题组 | 任务 | 必须保留的语义 |
| --- | --- | --- |
| IC1–IC3 | 同名朋友、最近消息、到访国家 | 最短朋友距离、边界日期、去重、排序和 limit |
| IC4–IC6 | 新话题、新论坛、标签共现 | 时间区间与历史排除、成员关系、聚合对象与计数 |
| IC7–IC9 | 点赞者、回复、二度朋友消息 | 每人最新点赞及并列处理、直接回复、消息排序 |
| IC10–IC12 | 推荐、工作、主题专家 | 精确距离与月份条件、工作年份、标签分类层次 |
| IC13–IC14 | 最短路径长度、全部最短路径及权重 | 不可达、路径方向、所有最短路径、互动权重 |
| IS1–IS7 | 用户、朋友、消息、作者、论坛和回复 | 完整投影、内容/图片选择、递归追溯原帖、排序 |
| IU1–IU8 | 用户、点赞、论坛、成员、消息、朋友写入 | 原始 ID、时间、关联边、事务提交与读取可见性 |

每题的完整谓词、排序和投影以链接到的固定参考查询为准，Java 字段以固定 driver 为准。
Cypher 列别名和 Java 结果字段存在差异时，由适配器显式转换并测试，不能依赖名称碰巧一致。
参数表保留构造器变量名与 `@JsonProperty` 名称；它们是两种接口描述，不能直接混为一份 wire schema。
IU7 的两个构造器 JSON 名称与字段名有差异；实际 Jackson 2.13.2 往返检查通过，
`parameterMap` 和精确 Long 值都保留。检查范围及完整 driver 验收要求记录在 `compatibilityNotes` 中。

## 固定数据与参数

1. `candidates/sf100.json` 已冻结三份 SF100 资产的 SHA-256 与字节数，成员清单见 `assets/sf100/inventories.json`。执行机获取或复用时仍须按锁重新校验。
2. 记录转换器、schema、索引、Loader、数据库、driver、adapter 的源码与构建产物身份。
3. 导入校验保留逐分片计数、内容与关联完整性；进程退出 0 不能代替数据库核对。
4. 复杂读使用对应 SF100 的官方参数；短读使用官方 driver 的关联派生；更新保留时间与依赖。
5. 基准开始、每次独立重复和 A/B 之间，恢复相同初始状态并从同一流位置开始。
6. 参数流、更新流、随机种子、已执行范围和恢复状态摘要进入证据包；中断测量不拼接。

初始归档中的 `static/`、`dynamic/` CSV 才是初始图；同包的 `updateStream_*.csv` 需校验但不导入初始图。
正式更新仅使用 catalog 中 `updates-sf100` 的文件。SF100 内嵌 forum 流与单独包字节数/行数相同但 SHA-256 不同，
语义配套关系仍需独立参考重放验证；不得互换、拼接或把更新条数当作初始边数。

不在包内假造 SF100 参数定值或参考答案。应以固定参考实现对相同初始图生成
有序验证记录；保留生成配置、参考实现/数据库版本、数据与结果 hash、全部失败记录。
参考数据库和 HugeGraph 都按顺序执行同一条含更新的操作流，保持写入依赖和状态一致。
生成与实际验证是独立步骤。参考实现自身失败、序列化异常或缺少操作类别时，参考包不能发布。

## 答案校验

本包自带 Python 标准库校验器，不依赖 CLI、npm 或在线服务：

```bash
python3 verify.py verify
python3 verify.py questions
python3 verify.py questions --id IC14
python3 verify.py answers --reference validation.csv --reference-sha256 SHA256 --actual observations.ndjson
```

`validation.csv` 使用官方的单行 `操作JSON|预期结果JSON` 格式。结果含 `|` 时按 JSON 边界解析。
每条 actual 为一行 JSON，字段严格限定为：

```json
{"sequence":1,"operationId":"IS5","requestSha256":"<操作 JSON 原始 UTF-8 字节的 SHA-256>","status":"success","result":{"personId":42,"firstName":"张","lastName":"三"},"committed":false}
```

`sequence` 从 1 开始且严格递增。摘要不包含分隔符或行尾，也不重排操作 JSON 的字段。
actual 必须记录每个操作，包括失败：`success / timeout / error / unsupported / cancelled`。
写入成功的 `result` 为 null，`committed` 为 true；只读的 `committed` 必须为 false。
固定 driver 的参考记录将写入无结果值序列化为字符串 `"-1"`；它与 actual 中的 null 分别处理。
所有 29 类都留在分母中。缺类、漏行、超时、未支持或未确认提交会阻止 `answers-match`。
额外行、重复/乱序行、请求身份不匹配和损坏参考文件作为无效证据退出。
操作参数的完整解码和可执行性由 driver 验证；离线答案校验器核对操作类别及请求原文摘要。

- 整数由 Python 精确解析，拒绝 float、bool、越界数字和用字符串替换整数。
- 字段集合、类型、大小写和 Unicode 值都必须匹配；缺字段、null、空字符串分别处理。
- 普通多行结果保留参考排序；IC1 的集合字段和 IC12 的标签按多重集比较，重复次数保留。
- IC14 保留路径内顶点顺序，要求权重降序，同权重路径之间允许换序；权重为 0.5 的非负整数倍并精确比较。
- 读取不完整响应、只取前 N 行、只验证 count 或仅返回成功状态，均不能替代完整答案比较。

这是一道 HG-Bench 补充校验，独立于官方 driver 验证。`answers-match` 只说明所提交观测与参考答案匹配；
它不认证观测来源，也不能单凭更新回执证明事务已写入正确状态。最终验收还需真实 driver 有序验证、
写后读取/状态核对和完整导入核对，分别保留证据。任何本地命令均不会宣布官方 LDBC 审计通过。
输出遵循 `scorecard.schema.json`。此命令没有审计数据集来源，因此固定返回 `datasetIdentityVerified:false`、
`referenceScale:null`；任何规模的答案文件都不能仅凭这个结果被当作 SF100 验收证据。

## 测量、成绩和比较

`scoring-policy.json` 固定成绩字段、无效条件和比较规则；`calibration-plan.json` 固定校准实验设计。
`sf100-plan.json` 是待环境校准的运行配置。TCR、缓存、预热和计量时长尚未定值，正式运行必须拒绝缺项。
所有待定参数在正式运行前写入新的环境 profile 并冻结，不能看到 A/B 结果后修改规则。

计时覆盖提交至完整结果消费与声明的解码边界。调度时间、实际开始和完成时间分别记录；
服务时间与从计划时间起的端到端延迟分别展示。时间使用单调时钟计算时长，跨机时钟偏差另行披露。
错误、超时、late/dropped 和窗口边界操作保留；官方结果日志校验、HG 补充统计分别给出。

每类报告吞吐、延迟分布、错误、排队、验证覆盖和样本量；同时报告 Server、PD/Store、驱动和主机资源。
不设综合总分，不将不同规模/后端/入口混合排名，不将通过的类别均值代表完整题集。
先通过身份、完整性、正确性、调度和环境质量门，再讨论可比性；未经校准仅展示描述性结果。
bootstrap 和比较的单位为独立重复/配对区组，单次运行内请求不能冒充独立实验样本。
具体比较算法实现、可交互离线 HTML、完整任务调度属于第二阶段。

## 发布与复现

`bundle.lock.json` 锁定本包规范、源码、校验器与候选配置。它是完整性清单，不是发布者签名。
`verify --require-release` 在真实验收缺失时退出 3；离线校验不会通过手改布尔值升级为正式发布。
不包含数据下载、数据库启动、写入、服务重置、性能执行或远端操作。
toolchain 中的 `tools/pack-ldbc-spec.py --out 新文件.tar.gz` 可产生确定性独立包；
归档仅包含锁定规范和源码，不包含图数据。相同输入重复打包得到相同 SHA-256，已有输出不会被覆盖。

第二位贡献者应从干净环境按版本锁重建并验证真实结果，再记录环境、执行命令、证据 hash 和差异。
SF100 下载、转换、导入、参考答案生成及正式校准的任务预算独立确认；本包校验不触发这些任务。
修改语义、参数流、答案规则或 profile 需新版本；只修复说明文字也更新包摘要并记录变更。
